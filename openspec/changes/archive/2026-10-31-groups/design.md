# Design

## Context

Зачем фича - в proposal.md, что именно должно работать - в `specs/contact-groups/spec.md`.

Что есть сейчас:

- Таблицы `contacts` и `notes` (`src/db/schema.ts`). Схему без импортов из `src/` копирует в Docker-образ скрипт тестовых данных - это ограничение остаётся
- Чтение данных - функции в `src/lib/contacts.ts` (`server-only`), запись - серверные действия в `src/app/actions.ts`: они сами проверяют входные данные (`src/lib/validation.ts`), пишут в базу и вызывают `revalidatePath("/")` и `refresh()`
- Имена сортируются по-русски (`collate "ru-RU-x-icu"`), поиск не различает «ё/е» (`translate(name, 'Ёё', 'Ее')`) - ICU в Postgres есть
- Главная `src/app/page.tsx`: компонент `Contacts` в `Suspense` грузит список и блок «Пора связаться» параллельно. Поиск (`SearchBox`) при вводе делает `router.replace("/?q=…")` - другие параметры адреса сейчас теряются
- Строки списка `ContactRows` - клиентский компонент: сервер отдаёт компактный массив, строка целиком - ссылка на карточку
- Карточка: строки `DetailRow` в `<dl>`; «Как часто общаться» (`KeepInTouchRows`) - образец сохранения сразу: `useOptimistic`, при ошибке сообщение и откат
- Форма нового контакта `ContactForm`: `useActionState(createContact)`, при ошибке значения возвращаются в `state.values`. Страница формы сейчас не ходит в базу
- Удаление контакта - `deleteContact`; заметки удаляются каскадом по внешнему ключу
- Включены Cache Components: запросы к базе в страницах - только внутри `Suspense`
- shadcn/ui стиль `base-nova` на `@base-ui/react` 1.8. В реестре shadcn есть `combobox` для `base-nova`: несколько значений, метки с крестиком (`ComboboxChips`), поле ввода внутри. Он подтягивает компонент `input-group` и уже установленные пакеты
- Тестов и тестовой библиотеки нет. В CLAUDE.md теперь Vitest и Playwright в стеке и TDD для кода приложения; владелец решил: e2e и CI - потом

## Goals / Non-Goals

**Goals:**

- Одно правило «одинаковые названия» в базе: уникальность держит индекс, а не проверка в коде, поэтому две вкладки не создадут дубль
- Миграция только добавляет таблицы: старая версия приложения работает с новой базой, откат образа безопасен
- Список на главной остаётся быстрым на 1000+ контактов: метки не раздувают ответ сервера
- Код фичи - через тесты: сначала красный тест Vitest, потом код. Логика групп живёт в функциях, которые можно проверить на настоящей базе

**Non-Goals:**

- Playwright, e2e и CI (решение владельца: потом). Экраны в этой фиче проверяются руками
- Тесты компонентов интерфейса: для них нужны jsdom и Testing Library - новые библиотеки, их сначала обсуждать с владельцем
- Тесты на уже существующий код (поиск, «Пора связаться»), кроме мест, которые эта фича меняет
- Тестовые группы в скрипте тестовых данных

## Decisions

### 1. Модель данных: таблица групп и таблица связей

- `groups`: `id` (identity), `name` - `text not null`, `created_at` - `timestamptz`, по умолчанию `now()`
- Уникальный индекс по выражению `lower(translate(name, 'Ёё', 'Ее') collate "ru-RU-x-icu")`: «Теннис», «теннис» и «ТЕННИС» - один ключ, «Ёлка» и «елка» - тоже. Регистр сравнивается по правилам ICU, как сортировка имён
- `contact_groups`: `contact_id` → `contacts.id` и `group_id` → `groups.id`, оба `on delete cascade`; первичный ключ `(contact_id, group_id)` - контакт не попадёт в группу дважды; отдельный индекс по `group_id` для фильтра и подсчёта
- Удалили контакт или группу - связи удаляет база сама, код удаления контакта не меняется
- Длина и пустота названия проверяются в коде (как поля контакта), не в базе

Альтернативы:

- Массив `group_ids` в `contacts` - нет внешних ключей: удаление группы пришлось бы вычищать по всем контактам руками
- Метки текстом в контакте - переименование группы требовало бы переписать все контакты
- Недетерминированная ICU-коллация для регистронезависимой уникальности - сложнее и ломает `like`; индекс по выражению проще

### 2. Функции данных в `src/lib/groups.ts`, их и тестируем

Серверные действия получают Next.js-контекст (`revalidatePath`, `refresh`, `redirect`) и без него в тестах не запускаются. Поэтому вся работа с базой для групп - в `src/lib/groups.ts` (`server-only`), а действия только проверяют ввод, вызывают эти функции и обновляют страницы.

- `listGroups()` - `id`, `name`, число контактов; порядок - `name collate "ru-RU-x-icu"`, затем `id`
- `createGroup(name)` - вставка; нарушение уникального индекса (код Postgres `23505`) превращается в результат «уже есть» с названием существующей группы (её находим по тому же выражению-ключу)
- `renameGroup(id, name)` - то же правило; переименование в то же название другим регистром - это та же строка индекса, ошибки нет. Группы нет - «не найдена»
- `deleteGroup(id)` - удаление; связи уходят каскадом
- `addContactToGroup(contactId, groupId)` - `insert … on conflict do nothing`: повторное добавление ничего не ломает. Нет контакта или группы (нарушение внешнего ключа, `23503`) - «не найдено»
- `removeContactFromGroup(contactId, groupId)` - удаление строки; если её уже нет, это не ошибка
- `insertContact(data, groupIds)` - переносится сюда или в `contacts.ts` из `createContact`: в одной транзакции вставляет контакт и связи через `insert … select id from groups where id = any(…)`. Группы, удалённые в другой вкладке, просто пропускаются (сценарий из спеки)

В `src/lib/contacts.ts`:

- `listContacts(search, groupId?)` возвращает у каждого контакта `groupIds` - массив id его групп (подзапрос `array(select group_id …)`)
- Фильтр: `exists` по `contact_groups`. Если группы с таким `groupId` нет (старая ссылка), условие не применяется - в том же запросе (`not exists (select … from groups …) or exists (…)`). Так главная грузит всё параллельно, без второго запроса
- `getContactGroupIds(contactId)` - для карточки

Метки - id, а не названия: сервер один раз отдаёт список групп (id, название, по алфавиту), а у каждого контакта только числа. Клиент проходит по общему списку групп и берёт те, что есть у контакта, - метки сразу по алфавиту, а ответ на 1000 контактов почти не растёт.

### 3. Проверка ввода в `src/lib/validation.ts` и ключ названия

- `GROUP_NAME_MAX_LENGTH = 50`; `parseGroupName(value)` - строка, пробелы по краям убраны, пусто - «Введите название группы», длиннее - `tooLong(50)`
- `parseGroupIds(formData)` - все значения `groupIds` из формы: только положительные целые (как `parseContactId`), без повторов
- `groupNameKey(name)` в отдельном модуле без `server-only` (например, `src/lib/group-name.ts`): `trim` → «Ё/ё» в «Е/е» → `toLocaleLowerCase("ru")`. Им поле выбора решает, показывать ли «Создать группу «…»». Это подсказка интерфейса; окончательное слово - за индексом в базе

### 4. Серверные действия

В `src/app/actions.ts`, по образцу `setContactFrequency` и `markContacted` (вызываются напрямую из клиентских компонентов, возвращают `{ error? }`):

- `createGroup(name)` → `{ group?: { id, name }, error? }`
- `renameGroup(groupId, name)`, `deleteGroup(groupId)`
- `setContactGroup(contactId, groupId, member: boolean)` - добавить или убрать. Одно действие на одно нажатие, а не «вот весь набор групп»: если нажать быстро два раза, итог совпадает с последним нажатием (Next.js выполняет действия одной вкладки по очереди, оба действия безопасно повторять)
- Каждое: проверяет id так же, как остальные действия, разбирает название через `parseGroupName`, вызывает функцию из `src/lib/groups.ts`, затем `revalidatePath("/")`, `revalidatePath("/groups")` и `refresh()`
- `createContact` дополнительно читает `parseGroupIds(formData)` и вызывает `insertContact`; при ошибке формы возвращает отмеченные `groupIds` в `state.values`, чтобы они остались отмеченными
- `deleteContact` не меняется: связи удаляет база

Альтернатива - `createGroup(name, contactId)`, который сразу добавляет контакт в новую группу одной транзакцией. Отказались: два простых действия уже есть, а случай «группа создалась, добавить не вышло» по спеке просто показывает ошибку.

### 5. Поле «Группы» - Combobox из shadcn/ui

- `combobox` добавляется командой shadcn актуальной версии в `src/components/ui/combobox.tsx` (вместе с `input-group`). Новых библиотек нет: это код поверх `@base-ui/react`
- Новый клиентский компонент, например `GroupPicker`: Combobox в режиме нескольких значений, выбранные группы - метки с крестиком внутри поля, ввод фильтрует список. Если `groupNameKey` набранного текста не совпал ни с одной группой и текст не пустой, последним пунктом - «Создать группу «…»». Выбор этого пункта вызывает `createGroup`; без отдельного окна подтверждения (в примере Base UI оно есть - нам не нужно)
- Поле ввода - `maxLength={50}`, как поля формы контакта
- Пункты списка на телефоне не ниже 44 px, как в выборе частоты
- Два способа использования:
  - карточка - `ContactGroupsRow`: строка `DetailRow` «Группы» после «Почта». Метки показываются сразу (`useOptimistic`), каждое изменение - `setContactGroup`; ошибка - сообщение под полем и откат, как в `KeepInTouchRows`. Новая группа: `createGroup`, затем `setContactGroup`
  - форма нового контакта - поле после «Почта»: выбор хранится в состоянии формы и уходит скрытыми полями `groupIds`. Созданная из формы группа сохраняется в базе сразу - поэтому она остаётся, даже если нажать «Отмена»
- Страница формы начинает ходить в базу за списком групп: форма рендерится в `Suspense` (Cache Components). Список групп внутри `GroupPicker` пополняется созданной группой сразу, не дожидаясь обновления страницы

Альтернативы:

- Список с галочками в `Popover` - нет встроенного поиска и меток в поле; пришлось бы собирать руками
- Отдельный экран выбора групп - лишний переход ради одного нажатия

### 6. Главная: ссылка «Группы», фильтр, метки

- В шапке главной рядом с «Добавить контакт» - ссылка «Группы» второстепенного вида (контурная кнопка). На телефоне - под кнопкой добавления, во всю ширину
- `Contacts` грузит параллельно: `listContacts(query, groupId)`, `listOverdueContacts()`, `listGroups()`. `groupId` - из `?group=`, разбирается как id контакта. Выбранная группа - та, что нашлась в `listGroups()`; не нашлась - «Все»
- Ряд фильтра (`GroupFilter`) - под поиском, только если групп больше нуля. Каждая позиция - ссылка `<Link>`: `/?group=ID&q=…` (запрос сохраняется), «Все» - `/?q=…`. У выбранной - `aria-current` и заметный вид. На телефоне ряд в одну строку с горизонтальной прокруткой, на компьютере переносится
- `SearchBox` получает текущую группу и добавляет `group` в адрес при вводе и в форму (скрытое поле) при Enter - иначе поиск сбрасывал бы фильтр
- Число над списком и пустые состояния - по спеке: с группой без запроса - `pluralize`, с запросом - «Найдено: N»; пустая группа и «никого не нашли в группе» - свои тексты в `EmptyState`
- `ContactRows` получает список групп и у каждого контакта `groupIds`; метки - небольшие `span` под именем и «кто это» внутри той же ссылки, с переносом. Ссылка на карточку остаётся одна на строку
- Блок «Пора связаться» не получает `groupId` - фильтр его не трогает
- Сообщение «Контакт добавлен» ведёт на `/?added=…` без фильтра - как сейчас
- Цвета, отступы, шрифты меток и ряда фильтра - только дизайн-токены

Альтернатива - фильтр без адреса, в состоянии компонента: после перезагрузки и по ссылке со страницы «Группы» фильтр бы терялся.

### 7. Страница «Группы» - `src/app/groups/page.tsx`

- Серверная страница с `Suspense` и заглушкой загрузки, как карточка; сверху `BackLink` «Все контакты»; заголовок «Группы»
- Создание - клиентский компонент: поле и кнопка «Создать»; при ошибке сообщение под полем, текст остаётся; после успеха поле очищается
- Строка группы: название - ссылка на `/?group=ID`, число контактов (`pluralize`), кнопки «Переименовать» и «Удалить»
- «Переименовать» превращает строку в поле с «Сохранить» и «Отмена»; ошибка - под полем
- «Удалить» - `AlertDialog` по образцу `DeleteContactButton`: «Удалить группу «…»?», число контактов, что контакты останутся и что вернуть группу нельзя
- Пустая страница - подсказка из спеки
- Заголовок вкладки - «Группы · Личная CRM»

### 8. Тесты: Vitest на настоящей базе

- `vitest` - последней стабильной версии, только в `devDependencies`; скрипты `pnpm test` (`vitest run`) и `pnpm test:watch`
- `vitest.config.ts`: среда `node`, псевдоним `@` → `src`; `server-only` подменяется пустым модулем (пакет специально падает вне серверной сборки Next.js; поведение кода это не меняет)
- База для тестов - отдельная база `<POSTGRES_DB>_test` в том же локальном Postgres из Docker. Адрес выводится из `DATABASE_URL` заменой имени базы - новых строк в `.env` не нужно. Перед запуском `globalSetup` создаёт эту базу, если её нет, и применяет миграции тем же мигратором, что `scripts/migrate.mts`
- Защита: если имя базы не кончается на `_test`, тесты не стартуют. Так тесты никогда не очистят рабочую базу
- Перед каждым тестом - `truncate contacts, groups restart identity cascade`; файлы тестов выполняются по очереди (`fileParallelism: false`), потому что база одна
- После тестов - закрыть соединение с базой
- Что покрываем тестами: `parseGroupName`, `parseGroupIds`, `groupNameKey`; функции `src/lib/groups.ts` (уникальность с регистром и «ё/е», переименование, удаление с каскадом, добавление и удаление связи, повторное добавление); `listGroups` (порядок, число); `listContacts` с группой и поиском, `groupIds`, старая ссылка на удалённую группу; `insertContact` с группами и с удалённой группой; удаление контакта уменьшает число в группе
- Что не покрываем автотестами: серверные действия (тонкие обёртки над проверенными функциями) и экраны - их проверяем руками, а потом e2e
- В README - команда `pnpm test` и что перед ней должна работать база в Docker

## Risks / Trade-offs

- [Сгенерированный Combobox может не совпасть с установленной `@base-ui/react` 1.8] → после генерации `pnpm lint` и `pnpm build`; если не собирается - обновить компонент командой shadcn или собрать поле из частей `@base-ui/react/combobox` напрямую
- [Ключ названия считается в JS для подсказки и в SQL для индекса, редкие буквы могут разойтись] → тогда поле покажет «Создать группу», а сервер ответит «Группа «…» уже есть»: дубля не будет, верным остаётся индекс
- [Названия с двойным пробелом внутри («Большой  теннис») считаются разными группами] → принимаем: убираем только пробелы по краям, как сказано в спеке
- [Карточка открыта, а в другой вкладке группу удалили] → нажатие на эту группу вернёт «не найдено» и откатит метку; `refresh()` обновит список групп
- [Нет e2e, а большая часть фичи - экраны] → решение владельца; сценарии экранов проверяем руками по спеке на телефоне (узкое окно) и компьютере, e2e добавим позже
- [Тесты пишут в тот же Postgres, где рабочая база] → отдельная база `_test`, защита по имени, очистка только её таблиц
- [Тесты требуют запущенный Docker] → так и задумано: без моков, на настоящей базе; в README написано
- [Много групп - длинный ряд фильтра на телефоне] → одна строка с прокруткой; если станет неудобно - отдельное решение владельца
- [Длинное название группы в метке или фильтре растягивает строку] → ограничение 50 символов; метка обрезается многоточием по ширине строки

## Migration Plan

1. `pnpm db:generate --name groups` создаёт `drizzle/0002_groups.sql`: две `CREATE TABLE`, внешние ключи с каскадом, уникальный индекс по выражению и индекс по `group_id`. Существующие таблицы и строки не меняются
2. Выкатка обычная: merge → образ → миграции разовым контейнером → новый образ → smoke `/health`
3. Откат - вручную, запускает владелец: предыдущий образ. Новые таблицы остаются в базе, старый код их не читает. Удалять их не нужно; группы снова станут видны, когда новую версию выкатят ещё раз
