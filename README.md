# Личная CRM

Приложение, где я веду контакты людей, которых знаю лично. Подробнее - `specs/01-продуктовая-идея.md`.

Что умеет:

- список всех контактов и поиск по имени (регистр и «ё/е» не важны)
- добавление контакта: имя, кто это, откуда знакомы, телефон, почта
- карточка контакта с заметками: после разговора дописываю, о чём договорились
- удаление контакта вместе с его заметками: сначала приложение спрашивает подтверждение

## Что нужно установить

- Docker Desktop (должен быть запущен)
- Node.js 20 или новее и pnpm

## Первый запуск

1. Скопировать шаблон настроек: `cp .env.example .env`
2. Заполнить в `.env` все значения (пароль - любой длинный случайный)
3. Установить зависимости: `pnpm install`
4. Запустить базу: `docker compose up -d`
5. Создать таблицы: `pnpm db:migrate`
6. По желанию - заполнить базу тестовыми данными (1000 контактов): `pnpm db:seed`.
   Срабатывает только на пустой базе, существующие данные не трогает.
7. Запустить приложение: `pnpm dev`
8. Открыть в браузере: http://localhost:3000

## Обычный запуск

```
docker compose up -d
pnpm dev
```

Приложение откроется на http://localhost:3000. Остановить - `Ctrl+C` в терминале.

Локально приложение и база доступны только с этого компьютера: входа по паролю нет, поэтому из сети их не видно.

## База данных

PostgreSQL работает в Docker. Настройки подключения лежат в файле `.env` - он не попадает в git.

Проверить, что база работает (в колонке STATUS должно быть `healthy`):

```
docker compose ps
```

Остановить базу (данные сохранятся):

```
docker compose down
```

Данные хранятся в Docker-томе `personal-crm_postgres_data`. Команда `docker compose down -v` удалит их безвозвратно.

## Выкатка на сервер

Приложение работает на https://app.olgamrzvcrm.ru. Входа нет (так в спеке): кто знает адрес, тот видит и меняет контакты.

Выкатка автоматическая: **каждый push в ветку `main` сам выкатывает новую версию**. Ход выкатки виден на GitHub, вкладка Actions:

1. GitHub собирает образ приложения по `Dockerfile` с тегом - SHA коммита - и кладёт его в GHCR
2. Копирует на сервер `deploy/compose.yaml` и `deploy/deploy.sh` и запускает `deploy.sh`:
   - поднимает базу
   - применяет миграции разовым контейнером из нового образа; упали миграции - новая версия не запускается, работает прежняя
   - запускает новую версию
   - проверяет `/health`: должен ответить 200, иначе выкатка красная
   - оставляет на сервере только текущий и предыдущий образы
3. Проверяет снаружи https://app.olgamrzvcrm.ru/health

Красный крестик в Actions - выкатка упала. Сама она ничего не откатывает.

### Что где на сервере

| Что | Где |
| --- | --- |
| Файлы выкатки | `/opt/crm/prod` (docker compose, проект `prod`) |
| Настройки и пароль базы | `/opt/crm/prod/.env`, права 600, шаблон - `deploy/.env.example` |
| Какая версия сейчас и до неё | `/opt/crm/prod/current-image`, `/opt/crm/prod/previous-image` |
| Данные базы | Docker-том `prod_postgres_data` |
| nginx | `/etc/nginx/sites-available/olgamrzvcrm.ru.conf`, блок `app.olgamrzvcrm.ru` |
| Ключ, которым заходит GitHub | секрет `DEPLOY_SSH_KEY` в репозитории, на сервере - строка `github-actions-deploy@personal-crm` в `~/.ssh/authorized_keys` |

### Команды

| Команда | Что делает |
| --- | --- |
| `ssh crm docker ps` | показывает, что запущено |
| `ssh crm docker logs --tail 100 prod-app-1` | последние логи приложения |
| `ssh crm cat /opt/crm/prod/previous-image` | какая версия была до текущей |
| `ssh crm bash /opt/crm/prod/deploy.sh SHA` | вручную выкатывает версию SHA, например предыдущую для отката; миграции при этом не откатываются |
| `ssh crm 'cd /opt/crm/prod && APP_IMAGE=$(cat current-image) docker compose -p prod run --rm seed'` | заполняет пустую базу тестовыми данными; если контакты уже есть - ничего не делает |
